# 📘 MACROSY 10.0 - Manual de Arquitectura

## 🏛️ Filosofía del Sistema

**"Programar es diseñar circuitos, no escribir instrucciones"**

macrosy 10.0 es un **meta-lenguaje de preprocesado** que convierte **declaraciones de alto nivel** en **código ejecutable**. Opera bajo el principio de **"Chip Design"** donde:

- **Las macros son circuitos integrados**
- **Los parámetros son el bus de datos**
- **`%_` es el cortacircuitos universal**
- **La expansión es la ejecución del microcódigo**

---

## 🧬 Estructura del Meta-Lenguaje

### 1. Directivas de Control

| Directiva | Función | Equivalencia |
|-----------|---------|--------------|
| `%assign` | Variables en tiempo de compilación | Registros de CPU |
| `%if/%elif/%else/%endif` | Control de flujo | Puertas lógicas |
| `%rep/%endrep` | Bucles | Contador de programa |
| `%macro/%endmacro` | Definición de circuitos | ISA (Instruction Set Architecture) |
| `%str` | Captura de strings | Memoria ROM |
| `%define` | Constantes | Literales en hardware |

### 2. El Cortacircuitos: `%_`

```
%_ = "Corta la corriente de esta línea en el bus de datos"
```

Cuando un parámetro es `%_`:
1. **NO se reemplaza** en la línea correspondiente
2. **La línea COMPLETA se elimina** del código generado
3. **El circuito se abre** en ese punto

**Analogía hardware:**
```
Parámetro normal  = Interruptor CERRADO (pasa corriente)
%_                = Interruptor ABIERTO (corta corriente)
```

## 🔌 Arquitectura de Macros

### Ejemplo: `%aplicacion_web`

```
                      [APLICACIÓN WEB CHIP]
                              │
        ┌─────────────────────┼─────────────────────┐
        │                     │                     │
    [BACKEND]            [FRONTEND]           [DATABASE]
        │                     │                     │
     [FLASK]              [REACT]             [POSTGRES]
        │                     │                     │
    [AUTH]               [API]               [CACHE]
        │                     │                     │
     [JWT]               [REST]              [REDIS]
        │                     │                     │
    [TESTING]─────────────────────────────────────────┘
```

### Sintaxis de la Macro

```asm
%macro aplicacion_web 7
    %## [DOCUMENTACIÓN EMBEBIDA]
    %## PARAMS:
    %##   %1 = backend (flask/django/fastapi) o %_ para omitir
    %##   %2 = frontend (react/vue/html) o %_ para omitir
    %##   %3 = base_datos (postgres/mysql/sqlite) o %_ para omitir
    %##   %4 = auth (jwt/sessions/oauth) o %_ para omitir
    %##   %5 = api (rest/graphql) o %_ para omitir
    %##   %6 = cache (redis/memcached) o %_ para omitir
    %##   %7 = testing (pytest/unittest) o %_ para omitir
    %## ============================================
    
    [CIRCUITOS]
%endmacro
```

## 🎯 Patrones de Uso

### Patrón 1: Chip Completo
```python
aplicacion_web flask, react, postgres, jwt, rest, redis, pytest
```
**Genera:** Aplicación full-stack con todo el ecosistema.

### Patrón 2: Backend-Only
```python
aplicacion_web fastapi, %_, %_, %_, graphql, %_, %_
```
**Genera:** Solo API GraphQL sin frontend.

### Patrón 3: Frontend-Only
```python
aplicacion_web %_, vue, %_, %_, %_, %_, %_
```
**Genera:** Solo aplicación Vue.js.

### Patrón 4: Microservicio
```python
aplicacion_web flask, %_, postgres, %_, %_, redis, pytest
```
**Genera:** Backend con DB y caché.

## ⚙️ Mecanismo de Expansión

### Fase 1: Análisis
```python
# Entrada
aplicacion_web flask, %_, postgres, %_, %_, %_, %_

# Parámetros parseados
args = ["flask", "%_", "postgres", "%_", "%_", "%_", "%_"]
```

### Fase 2: Evaluación de Cortocircuitos
```python
# Para cada línea, si el parámetro es %_, la línea se elimina
%1 = "flask"   → Línea 1: SE GENERA (backend)
%2 = "%_"     → Línea 2: SE ELIMINA (frontend)
%3 = "postgres" → Línea 3: SE GENERA (database)
%4 = "%_"     → Línea 4: SE ELIMINA (auth)
%5 = "%_"     → Línea 5: SE ELIMINA (api)
%6 = "%_"     → Línea 6: SE ELIMINA (cache)
%7 = "%_"     → Línea 7: SE ELIMINA (testing)
```

### Fase 3: Generación
```python
# Solo sobreviven las líneas con parámetros NO-%_
# ===== BACKEND: flask =====
from flask import Flask, render_template
app = Flask(__name__)
# ... código de flask

# ===== BASE DE DATOS: postgres =====
import postgres
class Database:
    # ... código de postgres
```

## 🧠 Meta-programación Avanzada

### Nivel 1: Macros que generan macros
```asm
%macro generador_de_apps 1
    %macro app_generada 6
        aplicacion_web %1, %2, %3, %4, %5, %6, pytest
    %endmacro
%endmacro

generador_de_apps flask
app_generada react, postgres, jwt, rest, redis
# → aplicacion_web flask, react, postgres, jwt, rest, redis, pytest
```

### Nivel 2: Macros con parámetros por defecto
```asm
%macro app_con_defaults 0-7 flask, %_, postgres, %_, rest, %_, pytest
    aplicacion_web %1, %2, %3, %4, %5, %6, %7
%endmacro

app_con_defaults  # → Usa todos los defaults
app_con_defaults fastapi, react  # → Sobrescribe primeros 2
```

### Nivel 3: Composición de chips
```asm
%macro microservicios 2
    %## Circuito 1: Servicio A
    aplicacion_web %1, %_, %_, %_, rest, %_, pytest
    
    %## Circuito 2: Servicio B
    aplicacion_web %2, %_, %_, %_, graphql, %_, pytest
    
    %## Bridge
    @app.route('/bridge')
    def bridge():
        return {"service_a": "%1", "service_b": "%2"}
%endmacro

microservicios flask, fastapi
```

## 🔧 Integración con Replit

### Estructura de Archivos
```
proyecto/
├── macrosy10.py          # El motor (tu código)
├── fuente.mac            # Código con macros
└── salida.py             # Código generado
```

### Workflow
```bash
# 1. Escribes macros en fuente.mac
# 2. Ejecutas el transpilador
python3 macrosy10.py fuente.mac salida.py

# 3. Replit ejecuta el código generado
python3 salida.py
```

### Comandos para Replit
```bash
# Instalación (si necesitas dependencias)
pip install flask postgres jwt redis pytest

# Ejecución directa
python3 -c "exec(open('salida.py').read())"

# Modo watch (desarrollo)
while true; do 
    python3 macrosy10.py fuente.mac salida.py
    python3 salida.py
    sleep 1
done
```

## 🚀 Lo que Replit (y las IAs) deben saber

### 1. No es código normal
```python
# ❌ Esto NO es Python
aplicacion_web flask, %_, postgres

# ✅ Esto es una DECLARACIÓN DE CIRCUITO
# Generará Python después de la expansión
```

### 2. `%_` es el interruptor principal
```python
# ❌ No es un placeholder
%_  # NO significa "valor por defecto"

# ✅ Es un CORTACIRCUITO
%_  # Significa "ELIMINA ESTA LÍNEA"
```

### 3. Todo es texto hasta que se expande
```python
# La macro es como un template
# La expansión es como la ejecución
# El resultado es código real
```

## 🧩 Extensibilidad

### Cómo añadir nuevos circuitos
```asm
%macro mi_circuito_personalizado 1
    %## NUEVO CIRCUITO: %1
    if "%1" != "%_"
        # Código personalizado aquí
        print("Mi circuito con %1 está activo")
    %endif
%endmacro

%macro aplicacion_web 8  %## Ahora con 8 parámetros
    # ... código existente ...
    
    %## CIRCUITO 8: PERSONALIZADO
    mi_circuito_personalizado %8
%endmacro
```

### Cómo crear familias de macros
```asm
%macro app_rapida 0
    aplicacion_web flask, %_, sqlite, %_, rest, %_, %_
%endmacro

%macro app_empresarial 0
    aplicacion_web django, react, postgres, jwt, graphql, redis, pytest
%endmacro

app_rapida      # Para prototipos
app_empresarial # Para producción
```

## 🎯 Principios de Diseño

1. **Centralización:** Una macro = Un sistema completo
2. **Composición:** Macros dentro de macros
3. **Cortocircuito:** `%_` para habilitar/deshabilitar
4. **Documentación embebida:** `%##` en cada macro
5. **Versionado semántico:** Cambios en parámetros = Nueva versión

---

## 💡 Filosofía para la IA

**"No escribas código, diseña chips"**

Cuando uses macrosy 10.0:

1. **Piensa en circuitos** (no en líneas de código)
2. **Usa `%_` como interruptores** (no como placeholders)
3. **Cada macro es un chip** (no una función)
4. **Los parámetros son el bus de datos** (no argumentos)
5. **El código generado es el output** (no el source)
